## 1. 核心判断

**下一轮最值得做的是：连续缩小查找范围、原图快速预览、可靠找回上下文。** 当前已有中文片段搜索、筛选、收藏、标签、集合、分页、虚拟网格和最近活动；主要短板是这些能力尚未构成顺畅的连续查找流程。

证据分级：**A**＝本轮真实桌面或只读数据库实测；**B**＝当前源码调用链确认，并参考现有测试；**C**＝推测风险，尚缺针对性实测。测试通过不等于每个场景完成桌面验收。

| 核心问题 | 证据与影响 | 强度 |
|---|---|---|
| 范围与筛选不能自然叠加 | 切换导航分区会清空所选文件夹、集合及类型；类型、收藏、缺失共用一个互斥字段。用户不能顺畅表达“这个素材包里收藏的图片”。标签侧栏只有名称展示，没有点击筛选回调。 | B；跨多个库的完整任务未做 GUI 复现 |

## 2. 当前能力与查找流程

### 当前基线

真实 Windows Tauri 开发窗口已启动并交互，使用现有本地数据库，没有用浏览器模拟数据。窗口截图为 1443×931 像素。只读数据库统计：**1 个资源库根目录、688 项资源，全部为 image；0 条资源标签关联、0 个集合、0 条近期活动；中文文件名为 0**。数据库历史文件体积不代表当前资源条数。

已接通的能力：

- 搜索请求经 `src/api/tauri.ts` → Tauri command → Rust SQL。三个及以上 Unicode 字符使用 trigram FTS；一、二字符采用转义后的 LIKE；多个词之间为 AND，选定字段之间为 OR。现有 Rust 测试覆盖中文中间片段、字段隔离、组合条件和总数一致性。
- 已有大小、尺寸、修改日期、库、集合、收藏、缺失及类型条件；SQL 能组合其中多项，但前端导航会清除部分状态。
- 网格首批 200 项，手动“加载更多”，虚拟化只渲染可见区域及缓冲行；已具备两档密度，无需再建议“增加分页/虚拟列表”。
- 图片缩略图、详情路径、备注、收藏、标签编辑、集合整理已有实现；当前样本没有整理数据，不能据此宣称标签和集合完整桌面验收通过。
- MP3/WAV/OGG 和 MP4/WebM 有原生媒体控件、自定义受限媒体协议和播放活动回调。**当前样本无音视频，播放、拖动进度、编码失败及切换停止仍未验证。**
- 最近活动支持时间/动作筛选、按资源聚合和分页。保留 30 天、全局最多 1,000 条是已有设计选择，不应直接定性为缺陷；应把期限告诉用户，长期保存使用收藏/集合。

## 4. 优先级建议

优先级按用户收益、频率、成本及证据确定。工作量为熟悉项目的单人开发加针对性验证的粗估，不是工期承诺。

### A. 立即改善：让范围和条件连续组合（P1，调整现有交互为主）

**问题与证据：** 场景 1、3、6、7；[App 导航清理](I:/GameResManger/src/App.tsx:729)、[侧栏回调](I:/GameResManger/src/App.tsx:806)、[条件条](I:/GameResManger/src/components/ActiveFilterChips.tsx:10)、[被隐藏的搜索说明](I:/GameResManger/src/styles.css:1729)。当前根目录/类型切换会清除条件；默认路径关闭与需求第 14.2 节“默认覆盖路径”不一致。

**根因：** 导航页面、资源范围与筛选维度混在同一状态操作中；回显不完整，不是 SQL 缺少基础搜索能力。

**方案：** 将库/集合范围、类型、收藏/缺失、搜索字段分成独立状态；切换左侧分区只改变入口。顶部持续显示“库：tinyswords ×／类型：图片 ×／收藏 ×”等，提供单项清除及明确的全部重置。显示简短搜索规则；零结果提供“包含路径搜索”“移除某项条件”“搜索全部库”三个有条件出现的动作，每次操作显式更新条件条。首版保留现有默认字段，但使“同时搜目录”直接可见，后续再根据命中质量决定是否默认开启。

**改进示例：** 原来选素材包→切类型后范围丢失；改后选包→图片→输入词始终在包内。搜索 Deco 无结果时，一次点击“包含路径搜索”可利用当前库已有 39 个路径命中，无需先整理标签。

**竞品依据：** Bridge 的目录与条件组合、Everything 的独立筛选；本轮没有借用其数据存储方式。

**实施影响：** `App.tsx`、Sidebar、Toolbar、FilterPanel、Chips、前端请求类型；现有 Rust 字段大体可复用，无需迁移源数据。类型和收藏状态拆分需迁移前端状态。约 2–4 人日，低至中风险；应把扫描/整理后查询刷新统一到此处。

**验收：** 用两个库、两种类型、一个收藏资源，按不同操作顺序得到同一交集；切换入口不丢范围；收起侧栏仍能知道当前范围；每个 chip 可独立撤销；字段全部关闭时明确提示；搜索失败不把旧列表伪装成新结果。

### B. 立即改善：原图快看与连续比较（P1，需要补充受限预览能力）

**问题与证据：** 场景 4；截图 02、03；详情 `img` 使用 thumbnail_path，缩略图生成器限制 320×320。卡片同名时需查看长路径才能区分。

**根因：** 缩略图被同时用于识别和精细判断，缺少完整候选预览流程。

**方案：** 选中图片后空格打开快看；默认适应窗口，提供 100%、放大、平移、透明棋盘背景；左右键切换当前候选，Esc 恢复选择和滚动位置。显示文件名、尺寸、相对来源目录。首版支持已有可解码图片，最多当前及相邻少量预读；超大图按需解码并设资源上限。

**改进示例：** 原来逐张看缩略图，细节不清再打开外部软件；改后在 Archer 结果中一次进入，连续查看各颜色与动作，返回仍位于原卡片。

**竞品依据：** Bridge 官方空格、缩放、左右键和 Esc 预览流程。首批不做轮播 Review Mode、图集拆分或序列帧播放器。

**实施影响：** Grid/Card/DetailsPanel 与新快看组件；Rust 增加按已索引 asset ID 读取图片的受限通道或应用缓存预览，不开放任意路径，不放宽全盘 asset scope。可参考现有媒体协议，但不能只把音视频白名单改成任意类型。需要处理格式、文件变更、缺失、内存和错误状态。约 3–5 人日，中风险，不改变原图。

**验收：** 64px 图、1536px 序列图、透明 PNG、超大图和缺失文件各一例；100% 显示来自原图而非放大 320px 缓存；连续检查 10 张候选仅需进入一次；Esc 后恢复原查询、卡片与位置；键盘可选卡且焦点不被预览吞掉；源文件大小/修改时间保持不变。

### C. 立即改善：统一使用记录并恢复查找上下文（P1，修复衔接并少量补功能）

**问题与证据：** 场景 5、8；[底部复制](I:/GameResManger/src/App.tsx:716)、[通用复制](I:/GameResManger/src/App.tsx:759)、[属性区复制入口](I:/GameResManger/src/components/DetailsPanel.tsx:249)。最近页只有时间和动作条件，切换分区清除范围/选择，网格内部滚动不持久。

**根因：** 相同“使用素材”动作有不同回调；活动视图与浏览状态彼此分离。

**方案：** 所有素材路径复制通过 `assetId + 路径变体` 的统一动作，剪贴板成功才记录。最近条目增加缩略图、文件名/路径关键词筛选及“返回上次结果”；同一会话保留查询、范围、排序、已加载页和滚动锚点。明确“近 30 天、最多 1,000 次活动”。原图快看稳定显示后可增加独立 `preview_image` 事件，普通卡片选中仍不计入；这是相对于原设计的新增范围，不能假称已有或复用音视频事件含义。

**改进示例：** 原来属性区复制后，最近页不一定有资源；改后从任一绝对/相对素材路径入口复制均可找回。到最近页看完，再返回查询结果无需重新选择素材包或滚动。

**竞品依据：** Everything 将查询历史和打开历史分开；Eagle 从预览重新定位选中资源。当前项目具体复制缺口来自源码，不是竞品推断。

**实施影响：** 统一前端动作服务、RecentActivityRequest 与后端查询、时间线缩略图、浏览快照。只改复制记录和会话恢复无需迁移表；`preview_image` 需扩展 SQLite CHECK、Rust/TS 枚举、计数、筛选及清理测试。建议首批先交付无迁移部分，图片事件依赖 B 后另一个小提交交付。约 2–4 人日，低至中风险。

**验收：** 每个素材路径复制入口成功后恰有一条活动，失败为零；记录读回含资源 ID；至少 41 个不同资源验证时间线跨页关键词检索，不能只在已加载 40 项中搜；返回结果保持查询/范围/选择/滚动锚点；收藏和备注修改后最近详情同步；重启保留活动，首批不承诺重启恢复浏览位置。

### D. 下一阶段：只读子目录导航及点击标签筛选（P2，需要补充功能）

**问题与证据：** 场景 2、3、6；Sidebar 只列根目录；AssetSearchRequest 没有独立目录路径及 tag ID 条件；标签行无 onClick。现有自由文本标签搜索不能替代精确标签筛选。

**根因：** 素材包结构和应用标签没有转化为可点击范围。

**方案/示例：** 从已索引 absolute_path 派生目录树，选 `Units/Blue Units` 后显示直接子项或含子目录资源，点击面包屑返回；点击“特效”标签施加精确 tag ID 条件，保留原库范围。没有标签时直接按目录找，不阻塞于整理任务。

**竞品依据：** Connecter 的包含子目录、Bridge 的源目录搜索。

**实施影响与优先级：** 新增目录查询/计数、精确路径边界与标签条件；先基于已有索引，不实时递归原目录。路径大小写、分隔符、同名前缀与重叠根目录需定义。约 4–7 人日，中风险，收益高但范围大于 A，独立交付。

**验收：** `Art/Blue` 不匹配 `Art/Blue2`；直接子项/递归两种结果正确；跨库同名目录不混淆；多词标签精确匹配；所有条件进入统一摘要；不复制、不改写任何素材。

### E. 下一阶段：相关性与可复用查询（P2，需要补充查询能力）

**问题与证据：** 场景 1、5、7；SearchToolbar 仅名称/大小/修改时间/类型排序，Rust 未按命中字段区分优先级；查询 state 没有保存入口。当前 32 项 Archer 排序是否符合偏好未做用户测量。

**根因：** 匹配与排序分开后缺少“为何命中”解释，也未保存常用条件。

**方案/示例：** 有关键词时增加可选“相关性”，先区分文件名精确/片段、标签/备注、仅路径命中；卡片注明命中字段及来源目录。可保存“Blue + 图片 + 当前库”为命名查询，新文件满足条件后自动出现，手动集合继续保存确定成员。

**竞品依据：** Eagle/Bridge 智能条件集合、Everything 书签。具体权重为待试验方案，不假称竞品算法。

**实施影响与优先级：** 搜索返回增加命中解释、白名单排序策略、查询配置本地持久化；约 3–6 人日，中风险。先收集 20 个代表任务，避免把短词和路径命中粗暴降权后漏掉有用结果。

**验收：** 保存后条件可读可编辑；旧查询在新增字段后兼容；明确比较首屏目标命中率和任务完成步骤；同名结果有稳定 ID 次序；收藏/集合与动态查询语义不混淆。

### F. 下一阶段：按页补齐数据并建立性能基线（P2，需要局部底层改造）

**问题与证据：** 场景 8；App 的 executeSearch/handleLoadMore 每次调用全量 listAssetTags；[仓库函数](I:/GameResManger/src-tauri/src/db.rs:267) 没有限制 asset IDs。Rust 分别查询列表和 COUNT，使用 OFFSET；不带唯一 ID 的同名排序存在稳定性风险。

**根因：** 网格虚拟化只限制 DOM，并没有限制标签传输、SQL 次数与累计内存。

**方案/示例：** 页面返回直接带本页标签；输入短暂防抖，中文 composition 结束后提交；新条件立即使旧请求失效，所有结果/加载/错误共用请求版本。为排序加 ID 稳定次序。先测再决定是否采用游标分页或大范围索引改造。

**竞品依据：** Bridge 的缓存与搜索范围提示是交互参考；本项数据库方案直接来自项目调用链分析，没有声称借用了竞品内部实现。

**实施影响与优先级：** App、命令响应类型、search/db、分页测试；局部改造约 2–4 人日，完整压测另计。大量标签用户收益高；当前 0 标签样本无法量化收益，不能优先重写整个搜索引擎。

**验收：** 后续在固定机器、Release 构建下，准备 1万/6万/10万条受控索引与真实图片样本；分别测冷/热缓存、1/2/3 字中文、字段组合、深分页。记录输入结束→首屏稳定的 P50/P95、SQL/IPC 用时、峰值内存和滚动帧时间。每组至少 30 次并记录 CPU/RAM/磁盘/WebView2 版本。先建立基线，再约定例如热查询 P95≤300ms 的目标；该数值是候选验收目标，不是本轮测量结果。

### 暂缓实施

AI 自动打标、视觉语义搜索、完整 3D/Spine 运行时、图集处理、云端协作继续作为单独决策项。Eagle 官方已有离线视觉/自然语言搜索相关资料，但仍涉及模型、硬件、索引和质量评估，不能因为“可离线”就默认纳入本项目。[官方 AI 搜索说明](https://en.eagle.cool/blog/post/eagle-plugin-ai-search)

同样暂缓一次性重做界面风格、无限制缩略图放大、引入 Everything 替代内部索引。这些不是当前最有证据的首批收益来源。

## 6. 其他项目风险

以下为源码审查发现，除明确标注外没有专项桌面复现。它们应进入正确性清单，不掩盖查找流程主线。

| 风险 | 证据、触发方式与处置 |
|---|---|
| 日期上界会排除所选日期的大部分时间（B，局部 SQL 验证 A） | FilterPanel 把起止日期都转成 UTC 零点，search 使用 `modified_at <= 上界`；选“到 9月19日”时，当天中午晚于零点。只读 SQL 示例返回 false。应按用户本地日历解释下界与“下一天零点”的排他上界，统一时间表示；增加跨时区/当天边界测试。 |
| 扫描/移除索引后当前网格可能不刷新（B） | 扫描结束和删除文件夹调用 loadData 更新 assets，但显示的是 gridAssets；当查询条件没有改变时没有保证执行 executeSearch。触发：全部资源视图下扫描完成，selectedFolderId 原本就是 null。建议统一资源变更后的查询失效机制。未在用户库重新扫描。 |
| 最近页和收藏详情可能使用过期数据（B） | selectedAssets 优先从 recentItems 取值；收藏和备注回调只更新 assets/gridAssets。最近页编辑后可能仍显示旧状态；收藏筛选中取消收藏只改 flag，不重新评估成员/总数。增加场景集成验证。 |
| 列表与总数缺少共同快照，分页同名排序无唯一键（B→C） | search_assets_page 先查行再 COUNT；扫描同时写入时可能看到不同状态。ORDER BY 最后仅 file_name，没有 id；稳定性风险不等于本轮已发现重复项。建议唯一 ID 次序，按实际并发需求评估只读事务/快照。 |
| 键盘可访问性不完整（B） | AssetCard 使用 div role=button/tabIndex=0 但没有 Enter/Space 键处理；目录/集合点击行缺少等价键盘入口。首批快看应一起补键盘选择、焦点返回。截图中的小字号仅标为风险，尚未测对比度。 |
| 扫描串行约束主要依赖前端（B） | start_scan 的锁和唯一约束按 folder_id；不同库并发调用不等于全局单任务。现有 UI 会禁用按钮，但后端与项目“同一时间一个扫描任务”约定存在差距。应新增全局门禁测试，再决定实现方式。 |
| 历史说明与当前实现有偏差（B） | 需求要求默认搜路径而 App 为 false；搜索规则 DOM 存在但 CSS 隐藏；v0.10 设计文档曾描述 convertFileSrc 媒体方案，当前实际为 asset-media 协议。后续以当前行为验收，更新文档时不要把设计目标当事实。 |

已核实的正面基础：lib.rs 已注册 SqlitePool、ThumbnailDir、ScanRuntime，不应重复报告历史“连接池未注册”问题；迁移及媒体协议现有测试通过；图片缩略图写入应用目录，缺失文件走索引标记；媒体请求按 ID 查索引并限制格式/范围。未做全面安全审计或对全部素材的前后哈希比对，因此不宣称证明了所有场景的数据安全。
