# v0.9 标签管理闭环设计

**日期：** 2026-06-12
**产品：** 游戏资源管理器 / Game Resource Manager
**状态：** 已确认设计，待实施计划

## 目标

补齐标签的全生命周期管理，以及单选和多选资源的标签解除能力。用户可以集中查看、重命名、改色、合并和删除标签，同时继续在右侧详情面板为当前资源添加或移除标签。

所有操作仅修改应用 SQLite 中的标签和资源关联，不删除、移动、重命名或修改任何原始素材文件。

## 范围

v0.9 包含：

- 标签管理器入口和弹窗。
- 标签名称、颜色和关联资源数量展示。
- 标签重命名。
- 标签颜色编辑。
- 重命名为已有标签时自动合并。
- 标签安全删除。
- 单选资源移除标签。
- 多选资源移除共同标签。
- 标签变更后的搜索索引和界面状态刷新。

v0.9 不包含：

- 标签层级或标签组。
- AI 自动打标。
- 标签导入或导出。
- 批量编辑原始素材文件。
- 云同步或团队标签系统。

## 产品语义

### 标签名称

- 保存前沿用现有 `normalize_tag_name` 规则：去除首尾空格、压缩连续空白并转为小写。
- 规范化后为空的名称必须拒绝。
- 重命名为当前标签名称是幂等操作。
- 重命名为不存在的名称时，直接更新当前标签。
- 重命名为已有标签名称时，不返回重名错误，而是执行自动合并。

### 自动合并

假设来源标签为 A，目标标签为 B：

1. 把 A 的全部资源关联以幂等方式加入 B。
2. 删除 A 的全部资源关联。
3. 删除 A 标签记录。
4. 保留 B 的名称和颜色。
5. 返回 B 的最新信息和关联资源数量。

整个过程必须在单个 SQLite 事务中完成。任一步失败时不得留下部分合并状态。

### 标签颜色

- 使用 `#RRGGBB` 格式。
- 保存前把十六进制字母统一为大写。
- 不接受短格式、透明度格式、颜色名或其他字符串。
- 修改颜色不影响资源关联。

### 删除标签

- 删除前必须显示二次确认。
- 确认文案必须明确：只删除应用内标签及其资源关联，不会删除或修改原始素材文件。
- 删除标签会删除对应 `asset_tags` 关系和 `tags` 记录。
- 删除标签不会删除 `assets` 记录。
- 删除不存在的标签返回未找到结果，不静默伪装成功。

### 当前资源标签操作

- 单选资源时，用户可添加标签，也可解除该资源已有标签。
- 多选资源时，界面显示共同标签；用户可从全部所选资源解除某个共同标签。
- 从资源解除标签仅删除 `asset_tags` 关系，不删除标签本身。
- 对不存在的资源标签关系重复执行解除操作应保持幂等。
- 空资源 ID 列表必须拒绝，避免产生语义不明确的成功结果。

## 架构

保持现有分层：

```text
React UI
  -> src/api/tauri.ts
  -> Tauri commands
  -> Rust db repository
  -> SQLite
```

前端不得直接访问 SQLite 或源文件系统。标签管理只通过类型化 Tauri command 执行。

## 后端设计

### 数据模型

扩展 Rust 和 TypeScript 的 `Tag`：

```text
id: number
name: string
color: string
asset_count: number
```

`list_tags` 按名称排序，并通过 `LEFT JOIN asset_tags` 返回关联资源数量。

### Repository 操作

新增以下 repository 能力：

- `update_tag(tag_id, name, color) -> Tag`
  - 校验并规范化名称和颜色。
  - 普通重命名或自动合并。
  - 在事务中刷新受影响资源的 FTS 数据。
- `remove_tag_from_assets(tag_id, asset_ids) -> removed_count`
  - 校验标签存在。
  - 幂等删除资源关联。
  - 刷新实际受影响资源的 FTS 数据。
- `delete_tag(tag_id) -> deleted`
  - 在事务中收集受影响资源 ID。
  - 删除标签及关联。
  - 刷新受影响资源的 FTS 数据。

现有 `apply_tag_to_assets` 行为保持兼容。

### 搜索一致性

标签名称参与 FTS 聚合字段。以下操作完成前必须刷新受影响资源的普通 FTS 和 trigram FTS：

- 标签重命名。
- 标签合并。
- 从资源解除标签。
- 删除标签。

刷新应复用现有数据库辅助逻辑，不在 command 层拼接搜索索引 SQL。

### Tauri Commands

新增：

- `update_tag`
- `remove_tag_from_assets`
- `delete_tag`

command 层只负责参数接收、调用 repository 和统一错误转换。

## 前端设计

### 标签管理器

左侧标签区域增加“管理”入口，打开模态弹窗，不新增应用路由。

管理器分为：

- 左侧标签列表：名称、颜色标识、资源数量。
- 右侧编辑区：名称输入、颜色输入、保存、删除。
- 删除确认区：安全说明、取消、确认删除。

保存重命名后：

- 普通更新：替换列表中的当前标签。
- 自动合并：移除来源标签，用返回的目标标签替换目标项。
- 列表始终按名称重新排序。

当前标签被删除或合并后，管理器自动选中下一项；列表为空时显示空状态。

### TagEditor

扩展 `TagEditor`：

- 已有标签 chip 提供明确的移除按钮。
- 通过 `onRemove(tagName)` 通知上层。
- 多选时仅传入共同标签，因此移除行为作用于全部所选资源。
- 添加建议和现有添加流程保持不变。
- 操作进行中应避免同一标签被重复提交。

### DetailsPanel 与 App

`DetailsPanel` 将标签移除请求转换为：

```text
tag identity + selected asset IDs
```

`App` 完成操作后：

- 刷新全局标签和最近标签。
- 刷新当前搜索结果及总数。
- 刷新当前选中资源标签。
- 显示成功或错误 toast。

为了避免 `DetailsPanel` 内部标签状态无法感知外部刷新，增加一个由 `App` 更新的标签刷新版本值，作为重新加载当前标签的依赖。

## 错误处理

- 空标签名：显示“标签名称不能为空”。
- 非法颜色：显示“颜色必须使用 #RRGGBB 格式”。
- 标签不存在：显示“标签不存在或已删除”。
- 合并或删除事务失败：不更新前端本地列表，并显示后端错误。
- FTS 刷新失败：整个事务回滚。
- 前端操作失败后保留当前输入和选中状态，方便重试。

## 验收标准

- 用户可以集中查看标签名称、颜色和资源数量。
- 用户可以重命名和修改标签颜色。
- 重命名为已有标签时自动、安全、原子地合并。
- 用户可以安全删除标签，且原始素材和资产索引不受影响。
- 单选和多选资源都可以解除标签。
- 解除资源标签不会删除标签本身。
- 标签变更后搜索结果、标签建议、共同标签和资源数量保持一致。
- 所有自动化检查通过。
- 应用不删除、移动、重命名或修改任何原始素材文件。
