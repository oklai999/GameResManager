- [ ] **Step 5: Implement bounded Range response**

Define a testable response:

```rust
pub struct MediaResponse {
    pub status: u16,
    pub mime: String,
    pub content_length: u64,
    pub content_range: Option<String>,
    pub body: Vec<u8>,
}
```

`build_media_response` must:

1. load asset by ID;
2. reject missing/index mismatch/unsupported extension;
3. open the exact indexed path read-only;
4. parse at most one `Range`;
5. seek and read only the requested segment;
6. use actual filesystem metadata length;
7. cap every returned Range segment to 1,024,000 bytes, matching Tauri's
   built-in asset protocol;
8. serve `HEAD` with no body;
9. serve a no-Range `GET` only when the file is at most 64 MiB;
10. return `413 Payload Too Large` for a larger no-Range request, rather than
    allocating the entire file.

The 64 MiB no-Range limit is a memory guard, not a maximum media file size.
Larger files remain previewable through byte Range requests. The desktop
prototype gate in Step 8 must verify that WebView2 uses Range requests for the
target MP4/WebM samples; if it does not, stop v0.10.1 implementation and revise
the approved design instead of widening permissions or loading the file whole.

- [ ] **Step 6: Register the custom protocol**

In `lib.rs` add `mod media;` and register an asynchronous protocol named
`asset-media` before `.setup(...)`. The installed Tauri 2.11 API is:

```rust
tauri::Builder::default()
    .register_asynchronous_uri_scheme_protocol(
        "asset-media",
        |context, request, responder| {
            let pool = context
                .app_handle()
                .state::<SqlitePool>()
                .inner()
                .clone();
            tauri::async_runtime::spawn(async move {
                let response = media::handle_protocol_request(&pool, request).await;
                responder.respond(response);
            });
        },
    )
```

`handle_protocol_request` obtains the managed `SqlitePool` through
`context.app_handle().state::<SqlitePool>()`; therefore retain the context in
the closure and clone the pool before spawning. The request URL shape is:

```text
asset-media://localhost/<asset_id>
```

On Windows, Tauri exposes it to WebView2 as:

```text
http://asset-media.localhost/<asset_id>
```

The handler must parse only a decimal positive asset ID and forward the request
`Range` header. Build:

```text
200: Content-Type, Content-Length, Accept-Ranges: bytes
206: plus Content-Range
404: unknown/missing file
415: unsupported media type
416: invalid range
413: no-Range request larger than 64 MiB
```

Use the exact Tauri 2 protocol handler API available in the installed crate; do not change this URL or response contract.
